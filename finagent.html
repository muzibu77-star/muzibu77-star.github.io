01问题与架构

研报里的数字要逐条对回原文，质控人手少、点评时效紧；监管现场检查通报反复点名“引用与原文不一致、来源未核实、日期错误、底稿缺失”。一个具体的导火索：有分析师用 AI 写周报，把 2024 年的国常会表述标成了 2026 年的新政策，模型写得很流畅，但数字和时点站不住。

核心判断：不让模型“审稿”。模型只负责把稿件里的数字抽成结构化断言，结论由确定性代码对回出处库给出；查不到依据的交给人，不替人下结论。

项目按“定义任务 → 出处库 → 评测集 → 免训练基线 → 只训最弱环节 → 多 Agent 产品化 → 一次性验收”推进，每个阶段先写定判据再运行。

02任务定义

  • 9 类可由程序复核的错误：改数字、单位、期间、口径、增速分母、更正后仍引用旧值、日期、出处、稿内前后不一致。
  • 4 类结论：一致 / 不一致（附原文值）/ 找不到依据 / 口径不明。
  • 舍入规则：末位半个单位内算一致，一个单位内记为舍入差；超出舍入范围的才算“实质性错误”。
  • 核对需求依据时逐个打开调研来源原文；其中一个保荐处罚案例实为现场检查发现的实质问题，不能证明“文档比对可发现”，据此把招股书一致性核查降为可选扩展。

03可溯源出处库

采集：带披露日的原始文件

从巨潮资讯下载 30 家发行人 2023–2025 财年年报 90 份与更正公告 2 份，共 25,224 页；另采集国常会、国务院、统计局、发改委、央行、证监会的政策与统计发布 1,855 篇。每份记录披露日与 SHA256，请求被拒、正文提取失败等情况写入收据。

解析：以 PDF 文本层为准

做法
MinerU 解析版面与表格，再把每个数值单元格对回 PDFium 文本层的字符区间和位置框；对不上的数字不进入事实库，也不做修正。为每个数字绑定行标签、列表头、单位与合并 / 母公司口径，缺失字段留空不猜。
取舍
四份年报 41 页上对比两档解析：轻量档快 20–80 倍，但认错 13 个数字（全部被文本层对照拦下）；标准档没有认错。
提速
发现 MinerU 自带的 llama.cpp 只打包了 CPU 后端（运行时 GPU 占用为 0），改用 vLLM 在 GPU 上提供 1.2B 文档模型服务：12 页耗时 1,248 s → 21 s，绑定结果与 CPU 版完全相同；全量 25,224 页 456 分钟、0 份失败。
结果
补充窄列逐字换行等版式规则后，对不上文本层的表格数字 19,194 → 8,678；最终沉淀约 53.7 万条带原文字符位置的表格事实，写入 SQLite，支持按数字精确查找与按发行人、截止日过滤的 BM25 页面检索。

质检：53 万条没法人工抽 10%，改成两层核查

  • 按 id 等距抽 10,134 条，用存储的字符区间回取原文，全部一致。
  • 用相邻年度年报的上期列做自动交叉验证，印证 69,915 条（13.1%）事实的数值、行标签与列角色；两边都有单位时单位不一致率 0.35%。
  • 12 页 260 条整页人工核对，查出的 5 条单位 / 类型错误已修入规则。

时点控制

核查只使用写稿日及以前披露的文件，并以更正公告覆盖旧数，避免用“未来才公布的信息”判定当时的稿件。

04逐数字核实评测集

  • 先划分再生成：按行业交错把 30 家发行人划为训练 / 开发 / 验收 16 / 6 / 8 家并冻结。阶段 1 调规则时看过验收发行人的页面，因此只承诺抽取、核查与训练没有见过验收发行人的评测样本。
  • 注入错误：从三大报表生成正确断言，每条只做一次有记录的改动得到错误断言；用两起真实财务更正生成“更正后仍引用旧值”。冻结训练 38,798 / 开发 2,049 / 验收 2,038 条，以 lock.json 记录哈希。
  • 真实写稿错误：用两个通用模型在“给 / 不给合并报表原文”两种条件下写 352 篇年报点评，对其中 12,309 个数字逐条核实，每个标签附原文字符区间或事实编号及推导算式。按固定种子抽 10% 交叉复核，一致率 96.9%–99.1%。

05免训练基线：抽取与判定分开

模型把点评中的数字抽成结构化断言，科目只能从该年报合并报表的科目清单中选；确定性核查器按截止日过滤、以更正公告覆盖、同比优先取当年年报的本期 / 上期两列，并对“不一致”判断错因。比率、自有口径指标等无法判断的情况交给人工。

首版出现 10 条误报，定位为上年比较数已被重述；改取当年年报两列后降为 0。

06本地抽取模型训练

为什么训
Qwen3.5-9B 免训练抽取在“不漏检”上与 API 模型相当，但开发集误报 46、抽取遗漏 77（API 模型为 10、18）。差距集中在抽取的准确性与完整性，所以只训练抽取环节，暂不换 27B。
协议
只改“是否训练”一个因素；用 192 篇训练集点评的核实标签监督，不以 API 模型为教师。训练前写定五项采用门槛：实质性错误漏检为 0、误报 ≤ 15、确认 ≥ 900、遗漏 ≤ 25 等。
显存
最长样本 9,735 token，单张 4090 放不下：FSDP 分片冻结权重；首次试跑在全序列 logits 转 FP32 时溢出，改为只对受监督位置分块计算交叉熵，在真实模型上与原实现数值一致。rank 16、72 次更新、约 40 分钟，峰值 14.6 GiB / 卡；评测用 vLLM 原生 LoRA，四卡各起一个服务并行。
结果
开发集误报 46 → 7、遗漏 77 → 4、确认正确数字 834 → 913，误报与遗漏均少于 API 模型。
如实记录：训练后暴露出核查器按绝对值比较比率的符号漏洞（−8.3% 被判一致）。修正发生在看过开发集之后，因此只记为“有条件通过”，以验收集为准。

07多 Agent 编排

LangGraph 流程与权限

  • 抽取 Agent 只看稿件与科目清单；确定性核查器给出结论；复查 Agent 只处理交给人工的数字，用工具检索与计算；修订 Agent 只为判不一致的数字写改写句；最后生成工作底稿。
  • 模型节点失败时不抛出：抽取失败则全部交给人工，其他节点失败只记录错误。
  • 修订建议由代码核对“除该数字外逐字不变”，628 条中 627 条通过，抽 30 条人工复核全对。

先对照单 Agent，再定混合规则

同一模型配 find_number、search_pages、page_text、calculate 四个受限工具直接审稿（截止日后披露的文件拒绝读取，计算用 AST + Decimal，不用 eval）。

两组结果交叉后发现：Agent 在流程交给人工的数字上判“错误”几乎都对，判“正确”却会混入错误。质控最不能接受漏检，于是规定复查 Agent 只能把数字标为不一致，判“正确”只作排序提示，数字仍交给人。

按数据删除无效节点

稿内前后一致性节点在真实稿件上产生的 19 组发现，经逐条人工核对全部是误报（模型写的点评很少自相矛盾），因此从流程中移除；该类错误改由核查器在模板断言上覆盖（200 / 200）。

08封存验收与误差分析

验收集为 8 家未参与开发的发行人、94 篇点评、3,256 个人工核实的数字，错误都是模型写稿中真实出现的，不是人工注入。候选版本冻结到具体提交，结果不再用于调参。预先写定五项判据：H1 安全（实质性错误漏检 ≤ 1）、H2 本地模型可替代 API、H3 训练有效，混合方案另写补充协议 H4 不新增漏检、H5 召回率至少提高 15 个百分点。

H1–H5 全部通过。复查 Agent 标出 688 个，其中真实错误 645 个；本地 9B LoRA 抽取的误报率、确认率不劣于 API 模型，相对免训练 9B 误报更低、确认更高、遗漏更少（按点评篇配对 bootstrap 区间均不含 0）。

误差分析：瓶颈在数据层，不在模型

验收集上约一半正确数字仍交给人工。按发行人拆分后集中在三家公司，原因是这些年报的报表在出处库中没有绑定上，而不是抽取模型。所以改出处库而不是继续训练：对 MinerU 把整列挤成一格的报表页改从 PDF 文本层逐行生成事实，采用附注中针对“报表”的单位声明。

09部署与人工核查

  • 本地复查 Agent 不达标：为让稿件不出本机，只把复查与修订 Agent 换成免训练 Qwen3.5-9B。判出率 70.3%（API 模型 96.3%），66 篇中 36 篇的复查答案无法解析；安全底线守住但未达标。部署采用“本地抽取 + API 复查”，复查本地化需要另训复查模型。
  • 人工核查证据页：交给人工的数字里，错误数字约 30% 带有 Agent“认为一致”的提示，因此页面把提示标为“参考，不作结论”。点击稿件中的数字，右侧显示原件 PDF 并框出位置（抽 20 张核对，19 张正确）、折算到稿件单位的候选值与 Agent 查证摘要；快捷键点选“一致 / 确有错误 / 跳过”，反馈只追加记录，不改底稿结论。
  • 让 Agent 自报证据失败，改由代码回填：要求复查 Agent 引用出处库事实编号，判出率 96.3% → 87.5%，编号多被写成“f1”之类的占位符，因此撤回；改为由代码记录 Agent 检索到的事实并回填进底稿，不改任何结论，开发集 59 / 59 正确。
  • 工程：stdio MCP 服务（check_draft 与三个查询工具），LangChain 模型适配层同时支持 API 与本机 vLLM；SSE 推送节点进度与抽取流式输出；268 项 CPU 测试全部通过；API 只用一个低价模型，全项目约 35 美元。

10边界与遗留

  • 改进后仍有约四分之一正确数字需要人工确认。
  • 复查 Agent 还没有本地化，稿件完全不出本机需要另训复查模型。
  • 评测稿件是模型写的，不是分析师的真实稿件；也还没有与真实质控人员做用时对比，业务价值有待验证。
  • 比亚迪 2023 年续表页有 180 条事实仍缺单位。
